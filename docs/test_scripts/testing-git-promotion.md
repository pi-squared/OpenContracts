# Test: Git-backed testing app with retained results and evidence labels

## Purpose

Verify the exact promoted source and existing-state bindings through the new
running app, then prove inspection preserved the research and media.

## Prerequisites

Use the [promotion workflow](../../databricks/docs/testing-promotion.md), an
explicit profile, successful source reviews/local gates and the verified Git
deployment receipt. Freeze the baseline, native IDs, package hashes, browser
executables, viewport and named checks privately before the new app starts.
Capture every retained table/media fingerprint in a read-only transaction.

## Steps

1. Verify the new app's resolved Git SHA, `databricks/app` path, successful/running
   status and complete bindings against the promotion and installation journals.
   Read the authenticated production asset and compare its bytes with the gated
   build. Confirm the two existing apps retain their IDs, deployments and bindings.
2. In a new Chromium context and a new Firefox context at 1440 × 1000, open an
   actual retained extract with an explicit terminal error and successful cells.
   Confirm the saved result grid and review tabs remain usable. Separately open a
   finished extract with failed fields but no parent error; distinguish its outcome.
3. Open a failed field's failure notice and close it. Verify the retained failure
   context/recovery guidance and zero retries or model calls.
4. Use a successful cell's native View Sources action to open its original PDF.
   Check the actual source membership and first target. With no focused evidence
   on ordinary entry, confirm highlights are mounted and pointer-away labels are
   hidden. Hover and then leave an eligible highlight.
5. Click source A and then B in the extract pane. Each target comes into view;
   its label stays visible with the pointer away while the prior label returns to
   hover behavior. Findings, quotations and source associations remain unchanged.
6. Identify an actual shared highlight point from native source geometry and
   positively verify its eligible rendered identities. Trusted stationary clicks
   visit every identity in order and wrap without clearing focus, changing plural
   membership, switching the finding or moving the PDF unexpectedly. If the
   retained data lacks an eligible overlap, admit and identify a network-only
   technical fixture separately; do not invent a backend association.
7. Exercise genuine keyboard focus/Enter/Space on an eligible highlight. Temporary
   labels, focused labels and the native pane remain consistent. Record browser
   capability limits honestly; software event support does not prove hardware.
8. Close every test context. Repeat the exact read-only baseline and native queries
   and compare tables, media, definitions/native IDs, original/corrected findings,
   quotation geometry and review state. Verify zero new saves/model/parser work.

## Expected results

Every named check has an actual successful result on the deployed source in both
browsers, or an explicit retained failure/limitation. Required acceptance remains
open for unresolved gaps. All original research/media/definitions match the
baseline. New identity grants and operational metadata are separately qualified.
Safe screenshots name browser, viewport, zoom, source and actual sample/fixture.

## Cleanup

Close only the owned browser contexts/processes and retain immutable private
receipts. No sample deletion, database reset, annotation creation, extraction or
model rerun belongs to this inspection. Preserve both original apps and shared
data. Publish the reviewed source/evidence and close #126 only after acceptance.
